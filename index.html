// distroless linux vm images

Boot the minimum.
Ship nothing else.

cnimbus compiles a real, unmodified Linux kernel plus BusyBox into a minimal, distroless-style VM image — declared in one file, a Nimbusfile, and assembled with zero runtime dependencies once built.

⬇ Latest Release ★ View on GitHub
sh — cnimbus 
# declare your image -- prepare reads this too (KERNEL/BUSYBOX/ARCH/VGA)
$ cnimbus init

# compile the kernel + BusyBox "pieces" (needs Docker, once)
$ cnimbus prepare --arch amd64 --out ./pieces

# assemble a bootable image -- pure Go, zero dependencies from here on
$ cnimbus build-disk --pieces ./pieces -o my-image.iso

Not a container. Not quite a unikernel either.

Same goal as MirageOS, Unikraft or OSv — single workload, no shell, no login, minimal attack surface — reached with a real mainline kernel instead of a purpose-built library OS.

🧬

Nimbusfile

A Dockerfile-style manifest declares the kernel, BusyBox version, architecture, and everything that runs at boot. One file drives the whole pipeline, and it's reproducible.

📦

Two-command split

prepare is the only step that touches Docker, compiling the kernel/BusyBox/iptables once. build-disk is pure Go — no Docker, no compiler, ever again.

🛰️

Live config, no reboot

The AGENT directive polls HTTP, VirtualBox Guest Properties, virtio-serial, VMware's backdoor protocol, or cloud metadata services — config changes reach a running VM in seconds.

🛡️

Signed, hardened boot

Kernel PGP verification, Ed25519-signed pieces, and pure-Go --secureboot/--uki signing — no shim, no MOK, no external signing toolchain.

🔥

Bare-metal capable

HARDBOOT builds real Ethernet and WiFi chipset drivers plus a static WPA supplicant, for images that boot real hardware from a USB stick — opt-in, inert by default.

🌐

IPv4 + IPv6 firewalling

FIREWALL/FIREWALL6 apply real, static iptables/ip6tables rules at boot — RFC 4890 ICMPv6 essentials auto-injected so IPv6 never breaks silently.

Boots where your infrastructure already runs

Reaches a working network and runs your userland binary the same way, everywhere.

QEMU · BIOS + UEFI VirtualBox VMware Player/Workstation Hyper-V · Gen 1 + 2 Proxmox Firecracker Bare metal · USB boot amd64 · arm64

Docker is the only prerequisite

No local Go install, no SDKs, no cross toolchains — for compiling cnimbus itself, or for running prepare.

sh — build from source 
# build cnimbus itself, entirely inside Docker
$ docker run --rm -v "$(pwd)":/src -w /src \
    -e CGO_ENABLED=0 -e GOOS=linux -e GOARCH=amd64 \
    golang:1.26.5 go build -o cnimbus ./cmd/cnimbus
